Project Overview

About This Project

Why I built this, what problems it solves, and how it fits into real-world data workflows.

Why I Built This

Manual CSV cleaning in Excel is repetitive and error-prone. I wanted a tool that instantly splits duplicates and unique rows with accurate statistics, eliminating human error from data preparation workflows.

Real-World Use Case

Marketing teams often merge lead lists from multiple sources, creating duplicates. This tool processes those CSVs automatically, giving them clean unique lists for campaigns and separate duplicate logs for auditing.

Problems Solved

Eliminates manual filtering, handles large files via streaming, provides instant analytics (total/duplicate/unique counts), and exports results in multiple formats (individual Excel files + ZIP archive).

Data Cleaning Importance

Dirty data costs companies millions in bad decisions. By automating duplicate detection at the ingestion layer, this tool ensures downstream analytics, ML models, and reports are built on trustworthy foundations.

System Design

Full Project Architecture

End-to-end data flow from user upload to processed download.

Frontend (React + Vite)

User interacts with drag-and-drop zone built with react-dropzone. UI components render conditionally based on upload state. Axios handles the HTTP POST request with multipart/form-data.

API Communication (Axios)

Axios sends the CSV as a File inside FormData to the FastAPI backend. CORS preflight is handled by FastAPI middleware. Custom headers return statistics (X-Total-Rows, etc.) in the response.

FastAPI Backend

FastAPI receives the UploadFile, validates the .csv extension, reads bytes into memory, and routes to the Pandas service layer. Uses async/await for non-blocking I/O during file handling.

Pandas Processing Engine

pd.read_csv() ingests the file from BytesIO. duplicated(keep=False) flags all duplicate occurrences. drop_duplicates() extracts unique rows. Results are written to Excel buffers and compressed into a ZIP.

CSV Analysis & Duplicate Removal

Three output files are generated: duplicates.xlsx (all duplicate rows), unique.xlsx (cleaned dataset), and duplicate_grouped.xlsx (comma-joined values for quick scanning).

Response Back to Frontend

StreamingResponse sends the ZIP bytes back with Content-Disposition inline. Frontend receives the blob, generates object URLs, and renders download cards for each file plus a master ZIP button.

Data Engine

Pandas Concepts Deep Dive

The core processing engine. Every Pandas method used, explained with syntax, real usage, and performance context.

I/O pd.read_csv()

Reads CSV data into a DataFrame. In this project, it reads directly from a BytesIO stream without touching the disk.

python
df = pd.read_csv(BytesIO(file_bytes))

Why Used

By wrapping raw bytes in BytesIO, we process files entirely in memory. This is 10-100x faster than disk I/O and essential for serverless deployments like Render where filesystem writes are ephemeral.

Detection duplicated()

Returns a boolean Series indicating duplicate rows. keep=False marks ALL occurrences, not just subsequent ones.

python
duplicate_mask = df.duplicated(keep=False) df_duplicates = df[duplicate_mask]

Key Distinction

keep='first' marks duplicates except the first occurrence. keep=False marks every duplicate row, which is what we need to show users the complete duplicate picture.

Cleaning drop_duplicates()

Removes duplicate rows and returns a cleaned DataFrame. keep='first' retains the original occurrence.

python
df_unique = df.drop_duplicates(keep='first').reset_index(drop=True)

Performance Note

Pandas uses hash-based algorithms under the hood (O(n) average time), making it vastly faster than nested Python loops (O(n²)) for deduplication.

Structure DataFrame

A 2D labeled data structure with columns of potentially different types. Think of it as an in-memory Excel sheet powered by NumPy arrays.

python
# Shape gives (rows, columns) rows, cols = df.shape # len() gives row count total = len(df) # Column names print(df.columns.tolist())

Memory Layout

DataFrames store data in contiguous memory blocks (C-arrays). This cache-friendly layout enables vectorized operations that run at compiled C speed, not interpreted Python speed.

Complete Pandas Service Code

Below is the actual production code from csv_service.py, annotated line-by-line to explain the data flow:

python
import pandas as pd import zipfile from io import BytesIO def process_csv(file_bytes: bytes): # Step 1: Read raw bytes into DataFrame without disk I/O df = pd.read_csv(BytesIO(file_bytes)) # Step 2: Boolean mask — True for ALL duplicate rows duplicate_mask = df.duplicated(keep=False) df_duplicates = df[duplicate_mask].reset_index(drop=True) # Step 3: Drop duplicates, keep first occurrence only df_unique = df.drop_duplicates(keep='first').reset_index(drop=True) # Step 4: Create single-column grouped view for quick scanning if not df_duplicates.empty: df_grouped = df_duplicates.drop_duplicates().copy() df_grouped["combined"] = df_grouped.astype(str).agg(",".join, axis=1) df_single_col = df_grouped[["combined"]] else: df_single_col = pd.DataFrame(columns=["combined"]) # Step 5: Write all 3 outputs to Excel buffers inside a ZIP zip_buffer = BytesIO() with zipfile.ZipFile(zip_buffer, "w", zipfile.ZIP_DEFLATED) as zf: for filename, dataframe in [ ("duplicates.xlsx", df_duplicates), ("unique.xlsx", df_unique), ("duplicate_grouped.xlsx", df_single_col), ]: excel_buf = BytesIO() dataframe.to_excel(excel_buf, index=False) excel_buf.seek(0) zf.writestr(filename, excel_buf.read()) zip_buffer.seek(0) stats = { "total_rows": len(df), "duplicate_rows": len(df_duplicates), "unique_rows": len(df_unique), } return zip_buffer, stats

Boolean Indexing

df[mask] filters rows where the mask is True. This is vectorized — no Python for-loops needed. The mask is a Series of booleans aligned to the DataFrame index.

reset_index(drop=True)

After filtering or dropping rows, the index may have gaps. reset_index rebuilds it from 0 to N-1. drop=True prevents the old index from becoming a new column.

to_excel() Export

Exports DataFrame to Excel format via openpyxl engine. Writing to BytesIO keeps everything in RAM. index=False omits the DataFrame index from the output file.

Vectorized Operations

astype(str).agg(",".join, axis=1) converts every column to string and joins them row-wise using C-optimized loops. Doing this in pure Python would require iterating rows and columns manually.

Workflow

CSV Processing Logic

Step-by-step internal flow from user action to final download.

1. User Uploads CSV

User drags a CSV file onto the react-dropzone area or clicks to browse. The file is validated by MIME type (text/csv) and restricted to a single file (multiple: false).

2. Frontend Sends Request

Axios creates a FormData object, appends the File, and POSTs to /api/v1/csv/process with responseType: 'blob' to receive binary data. A loading spinner renders during the async operation.

3. Backend Receives File

FastAPI's UploadFile descriptor streams the multipart data. The router validates the .csv extension and checks for empty files, raising HTTP 400 if invalid.

4. Pandas Loads CSV

pd.read_csv(BytesIO(file_bytes)) parses the CSV into a DataFrame. Pandas automatically infers column types, handles headers, and detects common delimiters.

5. Duplicate Rows Identified

df.duplicated(keep=False) creates a boolean mask where every row that appears more than once is marked True. This captures the first AND subsequent occurrences.

6. Clean Data Generated

df.drop_duplicates(keep='first') creates the unique dataset. A third grouped view collapses duplicate rows into comma-separated single-column strings for quick auditing.

7. ZIP Archive Created

Three Excel buffers are written into a single ZIP archive using Python's zipfile module with DEFLATE compression, reducing transfer size.

8. Response & Download

StreamingResponse sends the ZIP blob back. Frontend extracts custom headers (X-Total-Rows, etc.), generates object URLs via URL.createObjectURL(), and renders download cards.

What is a DataFrame?
Beginner

A DataFrame is a table with rows and columns, where each column can have a different data type.

Interview Answer

A DataFrame is a 2D labeled data structure with an index (rows) and columns. It supports mixed types per column and vectorized operations.

Professional

duplicated() vs drop_duplicates()?
Beginner

duplicated() tells you which rows are duplicates. drop_duplicates() removes them and gives you the clean data.

Interview Answer

duplicated() returns a boolean mask. drop_duplicates() returns a new DataFrame with duplicate rows removed. Both accept a 'keep' parameter.

Professional

duplicated() is a predicate function returning a boolean Series aligned to the original index. It does not mutate data. drop_duplicates() is a filtering function returning a subset. In our pipeline, we use duplicated(keep=False) to capture every occurrence of duplicates for the audit file, while drop_duplicates(keep='first') produces the clean unique dataset. Using both together gives users complete visibility and a cleaned export.

How does read_csv() work?
Beginner

It reads a CSV file and turns it into a DataFrame table that Pandas can manipulate.

Interview Answer

read_csv() parses delimited text into a DataFrame, inferring dtypes, handling headers, and supporting various separators, encodings, and na_values.

Professional

Pandas' read_csv() is a Cython-optimized parser. It memory-maps large files when possible, uses a tokenizer to split lines, and infers column dtypes in a two-pass process. By passing BytesIO instead of a filepath, we avoid filesystem overhead entirely — the parser reads directly from the in-memory buffer, which is critical for serverless backends where disk space and IOPS are limited.

Why use Pandas for CSV processing?
Beginner

It's much faster than writing your own Python loops to check for duplicates.

Interview Answer

Pandas provides vectorized, C-optimized operations for filtering, grouping, and deduplication that outperform pure Python by orders of magnitude.

Professional

Pandas leverages BLAS/LAPACK and Cython for vectorized operations. A duplicate check that would require O(n²) nested loops in Python is O(n) in Pandas via hashing. Additionally, Pandas' unified I/O interface (read_csv → process → to_excel) eliminates format conversion boilerplate. For this project, the entire processing pipeline fits in ~30 lines of Pandas code versus 200+ lines of standard library Python.

How to handle null values in Pandas?
Beginner

Use df.dropna() to remove rows with missing values, or df.fillna(0) to replace them with zero.

Interview Answer

Pandas uses isna()/notna() for detection, dropna() for removal, and fillna() for imputation. You can target specific columns or strategies (mean, median).

Professional

Null handling strategy depends on business context. df.isna().sum() gives a null audit. df.dropna(subset=['email']) removes rows critical for deduplication. df.fillna(method='ffill') propagates last valid observation. In production pipelines, I would add a null-reporting step before cleaning so data owners can audit what was removed or imputed.

What are vectorized operations?
Beginner

Operations that work on entire columns at once instead of looping through rows one by one.

Interview Answer

Vectorized operations apply functions to entire arrays via C/Fortran loops under the hood, eliminating slow Python iteration.

Professional

Vectorization delegates iteration to compiled C code operating on contiguous memory blocks. When we call df.duplicated(), Pandas calls a Cythonized groupby-hash algorithm that runs entirely in C-land. The Python interpreter is only involved once to return the result. This avoids Python's GIL and interpreter overhead, yielding 10-100x speedups. In our grouped column creation, astype(str).agg(",".join, axis=1) vectorizes string conversion and aggregation across 10k rows without a single Python for-loop.

How is Pandas memory efficient?
Beginner

It stores data in compact arrays and lets you choose smaller number types to save RAM.

Interview Answer

Pandas uses NumPy arrays (homogeneous, contiguous memory) and supports categorical dtypes, sparse structures, and chunked reading to minimize footprint.

Professional

Pandas stores columns as contiguous C arrays (ndarrays), not Python objects. Int64 columns use 8 bytes per cell, not 28+ bytes like Python int objects. Categorical dtype stores repeated strings as integer codes (crucial for duplicate detection where values repeat). For massive files, read_csv(chunksize=...) processes data in fragments. In our deployment, processing stays within Render's free tier 512MB RAM because Pandas' in-memory representation is far denser than native Python structures.

Real Experience

Challenges Faced

Problems encountered during development and how they were solved.

CORS Issues

During local development, the frontend on localhost:5173 could not communicate with the backend on localhost:8000. Browsers blocked the request due to the Same-Origin Policy. Solved by adding FastAPI's CORSMiddleware with explicit origin whitelisting, then restricting it to the production Netlify domain before deployment.

Render Cold Starts

Render's free tier spins down after 15 minutes of inactivity. The first request after idle takes 20-30 seconds to wake the container. Mitigated by adding a loading state with explanatory text in the frontend so users know the server is waking up, and considering a ping cron job for production use.

CSV Parsing Errors

Some CSVs had irregular quoting, mixed line endings (CRLF vs LF), or missing headers. Pandas' read_csv() with default settings would throw ParserError. Solved by wrapping the read in a try/except block and returning a 500 error with a descriptive message, advising users to check file encoding (UTF-8) and delimiter consistency.

Localhost vs Production API

Switching from localhost:8000 to the production Render URL required environment-based API base URLs. Implemented by storing the API URL in a config constant and using Vite's import.meta.env for potential future environment variable injection.
